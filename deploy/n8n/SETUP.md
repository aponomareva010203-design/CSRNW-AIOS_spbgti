# n8n для AIOS: установка и первичная настройка

n8n работает как «безголовый» движок автоматизаций: пользователи платформы
в него не заходят, учётные записи в нём не создаются. AIOS обращается к
public API от одного ключа владельца, права на автоматизации разграничивает
собственной авторизацией (владелец карточки / администратор).

Лицензия: использование внутри организации допустимо лицензией n8n
Sustainable Use License — платформа AIOS внутренняя, внешним пользователям
n8n не предоставляется.

## 1. Запуск

```bash
cd deploy/n8n
# обязательно смените пароль Postgres и задайте ключ шифрования
N8N_POSTGRES_PASSWORD='<случайный пароль>' \
N8N_ENCRYPTION_KEY='<случайная строка 32+ символов>' \
docker compose up -d
```

`N8N_ENCRYPTION_KEY` шифрует credential'ы в БД n8n: при утере ключа
сохранённые связи (SMTP и т.п.) становятся нечитаемыми. Храните его
в `.env` рядом с compose или в менеджере секретов, но не в git.

## 2. Учётная запись владельца и API-ключ (один раз)

Откройте n8n в браузере и создайте аккаунт владельца:

- с прокси: `https://n8n.176.108.244.194.sslip.io/` (см. nginx-n8n.conf);
- без прокси — временный SSH-туннель: `ssh -L 5678:127.0.0.1:5678 <vps>`,
  затем `http://127.0.0.1:5678/`.

Пароль: минимум 8 символов, цифра и заглавная буква. Владелец — единственный
аккаунт инстанса; больше пользователей в n8n не заводится.

Затем: **Settings → n8n API → Create an API key** (без срока действия или
с длинным сроком — ключ пропадает из UI только при удалении). Скопируйте ключ.

## 3. Подключение AIOS к n8n

Админ-панель → Настройки внешних API → раздел **n8n**:

- Адрес: `http://127.0.0.1:5678` (AIOS и контейнер n8n на одном сервере);
- API-ключ: вставьте ключ из шага 2;
- «Проверить связь» → `ok: true`.

Альтернатива без админки — переменные в `.env` сервера AIOS (приоритет ниже
настроек из админ-панели):

```
AIOS_N8N_BASE_URL=http://127.0.0.1:5678
AIOS_N8N_API_KEY=<ключ>
```

## 4. Проверка

1. В платформе (после входа): «Рабочее пространство» → «Автоматизации» →
   «Создать».
2. Соберите: триггер «Кнопка в AIOS» → шаг «ИИ-агент AIOS» (любой промпт).
3. «Запустить» — в блоке результата появится ответ агента.
4. «История» — запись выполнения со статусом success (список executions n8n).

Шаг «Письмо» дополнительно требует настроенного SMTP в админ-панели
(«Рассылка»): credential в n8n создаётся автоматически при сохранении
автоматизации с почтовым шагом.

## Обслуживание

- Бэккат: `docker compose exec n8n-db pg_dump -U n8n n8n > n8n-backup.sql`
  плюс volume `n8n_data` (шифрованные credential'ы завязаны на
  `N8N_ENCRYPTION_KEY`).
- Обновление: `docker compose pull && docker compose up -d`.
- Логи: `docker compose logs -f n8n`.

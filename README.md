# AIOS Технологического института

Веб-приложение «единая архитектура данных, моделей и прикладных сервисов» — интерфейс и API пилотного проекта AIOS, разрабатываемый через мастерские с коллективами Технологического института.

**Цели проекта:**

1. Переход к автономным исследованиям и разработкам.
2. Повышение конкурентоспособности команд.
3. Снятие барьеров доступа и передачи знаний и компетенций.

---

## Архитектура

- **Фронтенд** — статический сайт на чистых HTML/CSS/JS в каталоге `frontend/`, без шага сборки (`npm run build` лишь сообщает, что собирать нечего).
- **Бэкенд** — FastAPI-сервис в `api/`: каталог моделей (`GET /api/models`), агентный рантайм-харнесс (`POST /api/chat`, `/api/sessions`, `/api/runtime`), серверная авторизация и админ-раздел (`/api/auth/*`, `/api/admin/*`), данные из `data/` (`/data/*`) и статика `frontend/` по корневому пути.
- **Агентный рантайм** — `api/runtime/`: цикл «LLM ↔ инструменты» с SSE-стримингом, OpenAI-совместимый провайдер (настраивается из админ-панели; mock остаётся только в тестах), инструменты знаний/каталога/файлов, файловое хранилище сессий, сборка системного промпта из агентов и навыков.
- **Единая точка доступа** фронтенда к данным — `frontend/js/api.js`, публикующий `window.AIOS_API`. Переход на выделенный бэкенд достигается изменением только `BASE_URL` внутри него.

### API

Эндпоинт `GET /api/models` возвращает `ModelsResponse` со списком карточек `ModelCard`:

| Параметр | Тип | Описание |
|---|---|---|
| `source` | `spbti` \| `huggingface` | Необязательный фильтр по источнику; неверное значение отклоняется схемой (HTTP 422) |

Поля `ModelCard` (`api/schemas.py`):

- `id`, `name` — идентификатор и название;
- `source` — `spbti` (сделано в Технологическом институте) или `huggingface`;
- `provider`, `model_id` — поставщик и идентификатор на хабе;
- `image_url` — миниатюра;
- `description_ru` — описание (жёстко ограничено 200 символами на валидаторе);
- `tags` — список тегов;
- `access_url` — ссылка на модель;
- `is_placeholder` — флаг заглушки.

Текущий источник данных — встроенный seed-каталог (`api/catalog.py`). Планируется замена на Hugging Face Hub API без изменения контракта и интерфейса; токены Hugging Face на фронтенд не передаются.

## Запуск

### Docker

```bash
docker build -t aios .
docker run -p 8000:8000 aios
```

Приложение поднимется на `http://localhost:8000` (порт можно переопределить переменной `PORT`).

### Локально (Python + uvicorn)

```bash
сс
cp .env.example .env   # LLM можно задать позже в админ-панели; .env — запасной вариант
uvicorn api.main:app --reload
```

### Только статика

```bash
npm run dev   # npx serve . -l 5173
```

> Раздел «Репозиторий моделей» в этом режиме не заработает — он обращается к `/api/models`, поэтому нужен запущенный FastAPI (`api/main.py`).

## Развёртывание на VPS

Опробованная схема на этой машине (Ubuntu 24.04, доступ по IP без домена):

```
Интернет → https://88.218.66.212 (nginx :443, самоподписанный сертификат на IP)
              ↳ HTTP :80 — редирект на HTTPS
              ↳ reverse_proxy → 127.0.0.1:8000 (systemd-сервис aios.service, uvicorn)
```

- **Приложение** — юнит `/etc/systemd/system/aios.service` (User=csrnw, WorkingDirectory=каталог проекта, `Restart=always`): `sudo systemctl restart aios` подхватывает изменения кода.
- **nginx** — сайт `/etc/nginx/sites-available/aios` (симлинк в sites-enabled): `proxy_buffering off` и таймауты 300с для SSE-стриминга `/api/chat`.
- **Секреты** — `.env` (LLM-эндпоинт опционален; `AIOS_ADMIN_LOGIN`/`AIOS_ADMIN_PASSWORD` — стартовый администратор, создаётся один раз при пустом хранилище `.aios-runtime/users`).
- **HTTPS без домена** — самоподписанный сертификат на IP (`/etc/nginx/ssl/aios-ip.{crt,key}`, 10 лет, SAN=IP). Браузер покажет предупреждение — принять исключение. Let's Encrypt по голому IP сертификаты не выдаёт.

Переход на домен, когда появится: A-запись домена → IP сервера, затем `sudo apt install certbot python3-certbot-nginx && sudo certbot --nginx -d <домен>` (заменит самоподписанный сертификат и настроит продление).

**Шпаргалка по эксплуатации**

| Действие | Команда |
|---|---|
| Статус/рестарт приложения | `systemctl status aios` / `sudo systemctl restart aios` |
| Логи приложения | `journalctl -u aios -f` |
| Логи nginx | `tail -f /var/log/nginx/aios.*.log` |
| Конфиг nginx | `sudo nginx -t && sudo systemctl reload nginx` |
| Обновление кода | правка файлов в каталоге проекта + `sudo systemctl restart aios` |
| Бэкап (пользователи, токены, сессии) | `tar czf aios-backup.tgz .aios-runtime data` |
| Восстановление бэкапа | распаковать в каталог проекта + `sudo systemctl restart aios` |

## Авторизация

Серверная авторизация (`api/routers/auth.py`): регистрация, вход, выход и профиль — эндпоинты `/api/auth/*`. Пароли хранятся только в виде PBKDF2-хеша с солью (`api/runtime/users.py`; JSON-файлы в `AIOS_RUNTIME_DIR/users` — вне git и вне публично раздающегося `/data`). Server-side Bearer-токены живут 7 дней (`api/runtime/tokens.py`, `AIOS_RUNTIME_DIR/auth`). На фронтенде сессия лежит в `localStorage` под ключом `aios-auth-v1` (те же имя и роль читают `pilot.js` и `workspace.js`), изменение сессии оповещается событием `aios-auth-change`; истёкший токен автоматически разлогинирует при следующей загрузке страницы.

При первом старте (пустое хранилище) создаётся стартовый администратор — прежняя демо-учётка (логин — почта, пароль — `1234`); смените пароль после развёртывания. Новые регистрации получают роль «Пользователь».

### Админ-панель

Страница `admin.html` (пункт «Админ-панель» в меню пользователя с ролью «Администратор») показывает все регистрации: имя, логин, роль, дату регистрации и последний вход. Действия:

- смена роли «Пользователь» ⇄ «Администратор» (нельзя снять роль с последнего администратора);
- удаление пользователя с отзывом всех его токенов (собственную учётку удалить нельзя).

### Настройки внешних API (LLM)

Блок в админ-панели задаёт LLM для рабочего пространства **всех пользователей**: endpoint (Base URL), API-ключ и модель. Приоритет настроек: админ-панель (файл `AIOS_RUNTIME_DIR/llm.json`) → `.env` → не настроено. Настройки применяются на лету, без рестарта. Кнопки:

- **«Загрузить модели»** — выпадающий список моделей, доступных ключу на эндпоинте (подойдёт любой OpenAI-совместимый API: OpenAI, proxyapi.ru, OpenRouter, vLLM, Ollama);
- **«Проверить соединение»** — минимальный тестовый запрос с показом задержки и ошибки API;
- **«Сохранить»** — ключ хранится только на сервере, в API отдаётся маской (`sk-…1234`).

| Эндпоинт | Назначение |
|---|---|
| `POST /api/auth/register` | Регистрация: `{login, password, name}` → профиль (роль «Пользователь»; занятый логин — 409) |
| `POST /api/auth/login` | Вход → `{token, user}` |
| `POST /api/auth/logout` | Выход — отзыв текущего токена |
| `GET /api/auth/me` | Профиль по токену |
| `PATCH /api/auth/password` | Смена своего пароля: `{old_password, new_password}` (текущая сессия живёт, остальные отзываются) |
| `GET /api/admin/users` | [админ] Все регистрации |
| `PATCH /api/admin/users/{id}` | [админ] Смена роли: `{role}` |
| `DELETE /api/admin/users/{id}` | [админ] Удаление пользователя |
| `GET /api/admin/llm` | [админ] Текущие настройки LLM: `{configured, source, base_url, model, api_key_masked}` |
| `PUT /api/admin/llm` | [админ] Сохранить `{base_url, api_key, model}`; пустой ключ = прежний; применяется на лету |
| `POST /api/admin/llm/test` | [админ] Проверка соединения с LLM (можно с несохранённым черновиком) |
| `POST /api/admin/llm/models` | [админ] Модели, доступные ключу на эндпоинте (`GET {base_url}/models`) |

## Рабочее пространство

Чат-панель (`frontend/js/workspace.js`) доступна после входа с любой страницы: кнопка «Рабочее пространство» в верхнем меню и золотая плашка на главной. Панель наползает справа поверх страницы, растягивается за левую кромку (или кнопкой ⛶) до полного экрана. Разметку панели скрипт инъецирует в DOM, поэтому страницам достаточно подключить `js/api.js` и `js/workspace.js`.

Секция «Контекст» (чипы агентов/навыков и автоподгрузка знаний, каталога и файлов) убрана: ничего не подгружается в рабочее пространство автоматически. Подбор навыков и систем знаний появится позже — рекомендациями в самом чате (см. дорожную карту).

- **Модель** — задаётся администратором централизованно (админ-панель → «Настройки внешних API»); текущий статус виден в шапке панели (`GET /api/runtime`). Без настроенной LLM чат отвечает 503 с понятным сообщением.
- **Диалог** — потоковые ответы через агентный рантайм (`POST /api/chat`, SSE): текст печатается по мере генерации, вызовы инструментов показываются карточками, ошибки — событием в чате. Кнопка «＋» начинает новый диалог, транскрипт прошлой сессии восстанавливается при повторном открытии панели.

Администратор на странице пилота может:

- менять статусы артефактов кликом (цикл «не начато → начато → в работе → готово»);
- редактировать тематику и ФИО руководителя;
- добавлять строки проектов.

Остальные посетители видят таблицу только для просмотра. Данные пилота также сохраняются в `localStorage` (`aios-pilot-status-v1`, `aios-pilot-data-v1`).

## Агентный рантайм (харнесс)

Панель «Рабочее пространство» — клиент агентного рантайма `api/runtime/`:

```
сообщение → POST /api/chat → системный промпт (файлы api/runtime/prompts/*.md:
           базовая роль + агент + навыки) → цикл «LLM ↔ инструменты»
           (до AIOS_MAX_TOOL_ITERATIONS шагов)
           → SSE-события: session / delta / tool_call / tool_result / done / error
```

| Эндпоинт | Назначение |
|---|---|
| `POST /api/chat` | Сообщение ассистенту; ответ — поток SSE. Тело: `{message, session_id?, agent_id?, skill_ids?}`. Модель задаёт администратор; без настроенной LLM — 503 |
| `GET /api/sessions` | Список сессий (сводки) |
| `GET /api/sessions/{id}` | Полный транскрипт сессии |
| `DELETE /api/sessions/{id}` | Удалить сессию |
| `GET /api/runtime` | Статус: настройка LLM (`live`/`not_configured`) и модель, инструменты |

**Инструменты** (реестр `api/runtime/tools.py`, вызываются моделью в формате OpenAI tool-calling):

- `search_knowledge` — подбор RAG-баз (`data/rag_bases.json`) и онтологий (`data/ontologies.json`) по запросу; полнотекстовый поиск по корпусам подключается отдельным инструментом;
- `get_catalog` — каталог моделей/агентов/навыков;
- `read_file`, `list_files`, `write_file` — файлы `data/` в песочнице `AIOS_TOOLS_ROOT`.

**Провайдеры** (`api/runtime/providers.py`): любой OpenAI-совместимый эндпоинт (OpenAI, proxyapi.ru, OpenRouter, vLLM, Ollama); конфигурация — из админ-панели (приоритет) или `.env`. Без настроенной LLM `/api/chat` отвечает 503; MockProvider остаётся только в тестах.

**Сессии** (`api/runtime/sessions.py`) — JSON-файлы в `AIOS_RUNTIME_DIR/sessions` (по умолчанию `.aios-runtime/`, вне git). Транскрипт, включая вызовы инструментов, сохраняется после каждого шага.

Модули рантайма и авторизации покрыты смоук-тестами: `pytest` (см. `tests/test_runtime.py`, `tests/test_auth.py`).

## Данные и навыки

- `data/agents.json` — карточки агентов (ChemCrow, OpenHands, MetaGPT, ChatDev).
- `data/skills.json` — карточки навыков с ссылками на файлы.
- `data/models.json` — каталог моделей, загружаемый в `GET /api/models`.
- `data/skills/scimlchem-architect.md` — навык «AutoSciML-Chem Architect v3»: процедура от научного интервью и математической декомпозиции до blueprint и запуска Colab-MVP.
- `frontend/data/` — копия `agents.json` и `skills.json` для режима «только статика» (`npm run dev`, файл-сервер без бэкенда). Обновляйте вместе с `data/`.

Страница «Агенты» подгружает эти JSON-файлы лениво — при первом раскрытии соответствующего спойлера.
